Privacy

Last updated: October 2, 2026

Prereasoner analyzes the spreadsheet data and questions you submit so it can compute an answer and show the steps used to reach it. The reference service at chat.prereasoner.com is operated by MailRecipe LLC.

What we process

  • Files and spreadsheets you choose. In the Google Sheets™ add-on, this is limited to the visible, non-empty tabs in the current spreadsheet when you submit a question, including table names, columns, and cell values. The Excel add-in reads visible, used ranges in the open workbook when you submit a question, including values and column labels; filtered or hidden rows in a visible worksheet are included. It does not edit cells.
  • Your questions, conversation history, generated SQL, results, and reasoning traces.
  • Account and session identifiers supplied through Google, Microsoft, and Firebase Authentication.
  • For the Google Sheets™ add-on, the document ID needed to reopen the conversation associated with that spreadsheet for your signed-in account.
  • For the Excel add-in, a one-way hash of the workbook URL is used to reopen its associated conversation; the workbook URL itself is not stored for this purpose.
  • Operational data needed to secure, debug, and operate the service.

How answers are produced

The core engine builds and executes inspectable SQL against your data. It uses a frozen model as an encoder for intent and schema signals; no model on the service's servers writes SQL or invents the numerical answer, and the database computes it. When the engine cannot build a query on its own, it can ask Gemini for help as described below, and the answer says so.

Assistant processing. The hosted assistant uses Google's Gemini models on Vertex AI, in the service's own Google Cloud project. Assistant requests can include your messages, conversation history, attached table contents, table and column names, generated SQL, limited query results, and trimmed tool output. This processing is used to present results, handle ambiguity, orchestrate tools, and fill reference cells you explicitly request.

When the engine cannot build a query for a question on its own, it can ask Gemini to reword the question once or to propose one SQL query. That request contains the question, the table and column names, column types, foreign keys, and up to three example values per column. The engine still checks, runs and labels any query that results, and the database computes every number.

Google receives those requests through the service's Google Cloud project. Its handling is governed by the operator's Google Cloud agreement and is also described in Vertex AI data governance and the Google Cloud Privacy Notice. Prereasoner is working toward operating this assistant layer locally once a local model meets the required quality, latency, security, and cost standards. The calculation and verification path remains deterministic.

Service providers

  • Google Cloud and Firebase: hosting, authentication, databases, and reasoning-trace delivery. See Firebase privacy and security.
  • Google Cloud Vertex AI (Gemini): language processing for the hosted assistant features and the query fallback described above.

Microsoft sign-in for Excel uses Microsoft's standard identity response through Firebase Authentication. Prereasoner receives the resulting Firebase account/session identity; it does not call Microsoft Graph or store a Microsoft access token.

We process this data to provide the analysis you request, maintain your account and saved work, secure and debug the service, and meet legal obligations. Depending on the law that applies, the bases are performance of the service contract, legitimate interests in operating and protecting the service, and compliance with legal obligations. We do not treat a protocol field or a popup click as blanket permission for unrelated uses.

Data protection

Prereasoner uses administrative, technical, and organizational safeguards designed to protect Google user data against unauthorized access, use, alteration, disclosure, loss, or destruction:

  • Data is encrypted in transit using HTTPS/TLS. Application data stored in Google Cloud SQL and Firebase is encrypted at rest by Google Cloud's managed encryption controls.
  • Every application request requires a short-lived, server-verified Firebase identity token. Server-side ownership checks isolate each user's conversations, and Firebase rules limit reasoning-trace reads to the authenticated owner.
  • Cloud SQL is reached through an IAM-authenticated connector rather than an open database network. Runtime services use dedicated, least-privilege service accounts and a non-superuser database role.
  • Database credentials are stored in Google Secret Manager and are not embedded in client code or operational logs. Gemini is called with the service's own Google Cloud identity, so no model API key exists.
  • Request-size, row, rate, and storage limits reduce abuse and unnecessary data exposure. Production logs exclude spreadsheet rows, questions, conversation history, generated SQL, credentials, request bodies, and full error messages.
  • Human access to user content is prohibited except with the user's explicit permission for support, when necessary to investigate abuse or a security incident, or when required by law.

Storage and retention

Uploaded tables are stored in a conversation-scoped PostgreSQL schema. Conversation state and named workbook revisions, and spreadsheet conversation links are stored in application tables with verified user ownership. Conversations and Sheets conversation links expire after 90 days without activity by default. The service also limits each account to 100 stored conversations, 256 MiB of serialized source and workbook state, and 1 MiB per saved snapshot. Reasoning traces stored in Firebase Realtime Database expire after seven days by default. A daily retention job applies both policies.

Operational logs contain operation names, sizes, and error classes. They do not contain raw request bodies, questions, conversation history, generated SQL, credentials, spreadsheet rows, or full error messages.

Deletion

Deleting a conversation removes its owned PostgreSQL data and the reasoning traces indexed to that conversation. The delete-all action removes every conversation owned by the signed-in user and the user's complete reasoning-trace subtree. Deleting only the Firebase identity does not currently erase every PostgreSQL or trace record. For complete account-linked deletion, email mani.doraisamy@gmail.com.

Training and public data

Customer spreadsheet rows and data derived from them are not included in Prereasoner's training corpora and are not used to train or improve shared models. The frozen encoder used by the service is not updated from customer data. Public reference facts come from documented sources such as Wikidata and publisher datasets, under their respective terms.
